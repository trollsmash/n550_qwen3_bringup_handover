一、写入（S2C GUI 工具，两项）

1文件 bringup_s2c.bin0x800000005944 B

第 2 项不是文件，是往那个地址写一个立即数。别漏 —— 它是整套设计的支点： 程序会把它读回来比对，这是唯一能反证"PCIe 后门写 DDR 真的生效了"的手段。 没有它，"PCIe 没写进去"和"程序崩了"两种情况完全分不开。

二、放开复位

⚠ 反复换镜像时特别注意。 本核有 32 KB L1I，与 D-cache 之间不自动保持一致。 host 经 PCIe 写镜像对 CPU 来说属于"动态加载指令"。若走软复位（不断电）， I-cache 里可能还留着上一个镜像的指令，CPU 会接着跑旧程序 —— 现象是"明明重新烧了，行为却一点没变"，调试时越反复越容易撞上。

start.S 开头已经放了一条 fence.i 兜底。但如果遇到无法解释的 "改了没生效"，先断电重来再怀疑代码。

三、读回判读

先看这一个：

地址期望值含义
0x87F0001C0x00000000FAILMASK。只有它为 0 才算通过

⚠ 不要只看 STATUS。软失败之后程序会继续跑，STATUS 会被后续阶段覆盖， 最终可能停在一个看起来正常的值上。判定通过与否一律看 FAILMASK。

然后逐项核对：

地址期望值含义
0x87F000000xB00000AASTATUS：全部通过
0x87F000040x00000080vlenb = 128 字节（VLEN=1024 bit）
0x87F000080x42000000AME 自测 = 32.0f
0x87F0000C任意性能采样周期数（低 32 位）
0x87F00010任意同上（高 32 位）
0x87F000140x000003E8采样次数 = 1000
0x87F000180x00000080mtilem 回读 = 128
0x87F00020仅诊断AME_RAW：缓存同步前读到的值
0x87F00024仅诊断C_ADDR：结果缓冲的物理地址
0x87F000840x5A5AC3C3程序读到的 magic

串口 0x20100000（16550，8N1）上有完整日志，六步逐行打印。 串口没输出不代表失败 —— 优先看 mailbox。

四、故障速查

现象多半是什么怎么办
STATUS 读到 0 或一直不变CPU 没跑起来查复位是否真的放开、时钟是否有、镜像是否真写进了 0x80000000
STATUS = 0xB0000010 后不动卡在串口串口寄存器可能不响应；见下一行
mailbox 在推进但串口一个字都没有多半是物理连接或 UART 时钟寄存器排布已与硬件确认：DW_apb_uart，32 位访问、间距 4 字节，程序即按此编译。先查串口线序/电平与 UART 时钟是否给到，再查 UART 是否被复位拉住
串口有输出但是乱码波特率分频不对程序已按 UART 输入时钟 40 MHz 自动配好（DLL=21 + DLF=11，实际 115274 baud，误差 +0.06%）。若实际输入时钟不是 40 MHz，改 board.h 的 BOARD_UART_CLK_HZ 重编，分频值会自动跟着算。注意 DLF 在这里是必需的：只用整数分频偏 +3.34%，超出 16550 的容限
FAILMASK 的 bit3 置位（0x8）PCIe magic 不符确认第 1 步的第 2 项写了；读 0x87F00084 看程序实际读到什么。读到 0 说明那次写入没落到 DDR
FAILMASK 的 bit4（0x10）RVV 没使能或 VLEN 不对读 0x87F00004，应为 128
FAILMASK 的 bit5（0x20）AME 结果不对见下方"AME 失败的三种情形"
串口打出 *** TRAP ***发生异常记下 mcause/mepc/mtval，用 riscv-unknown-elf-addr2line -e deliverables/fpga/bringup_s2c.elf <mepc> 定位

AME 失败的三种情形

矩阵单元的访存绕过 L1D 直连 DDR，而 CPU 读写经过 L1D，两者的一致性只能靠软件维护。 因此 AME 自测失败时，先用 0x87F00020（同步前的值）与 0x87F00008（最终值）对照：

AME_RAW 0x87F00020AME_RESULT 0x87F00008结论
0xbf8000000x42000000缓存一致性问题，同步已生效，属正常
0xbf8000000xbf800000msce32 没把结果写进来 —— 查矩阵单元或回写地址
任意其它值矩阵单元算错了

0xbf800000 是 -1.0f，程序预置的哨兵值；读回它就意味着那次写入没被看到。

若落在第二种情形，可让 host 经 PCIe 直读 0x87F00024 给出的地址—— PCIe 读 DDR 不经过 CPU 的 L1D，能独立判断矩阵单元究竟写没写：

  • 该地址是 0x42000000 → 数据在 DDR 里，问题出在 CPU 侧的缓存失效
  • 该地址是 0xbf800000 或其它 → msce32 确实没写到这里

五、通过之后

第六步会回填性能采样数据，这是上板才能拿到、之前只能靠猜的数：

每次满 tile mfmacc 的周期数 = CYCLES / ITERS
decode 一个 token 需约 145500 次 mfmacc
  => 每 token 耗时 = 145500 × 周期数 / 40 MHz

之前的估算区间横跨一个数量级（0.2 秒到 3 秒每 token），拿到这个数就收敛了， demo 的呈现方式才有依据。把 CYCLES 和 ITERS 两个值发我，我来算。
