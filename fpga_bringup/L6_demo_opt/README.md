# L6 —— 算子优化版

在 [`L5_demo_CLP/`](../L5_demo_CLP/) 基础上做两项访存优化。
**输出与 L5 逐位相同**，其余配置全部一致（tile-major 权重、CLP 窗口、
回答上限 256、上下文 1024），可直接做 A/B 对比。

## 文件与地址

| 文件 | 写入地址 |
|---|---|
| `qwen3_s2c.bin` | 0x80000000 |
| `w.bin` | 0x88000000（与 L4/L5 同一份） |
| `tok.bin` | 0xD0000000（与 L4/L5 同一份） |

`w.bin` 和 `tok.bin` 与 L4/L5 完全相同，**只需换 `qwen3_s2c.bin`**
即可切换。CLP 窗口的重映射要求与 L5 一致。

放开复位前，往 0x87F00014 写一个 uint32 = 当前 UTC 秒
（`date +%s`），提示符会显示北京时间。

## 改了什么

### 1. attention 按 KV head 批处理

原来对**每个** query 都从头扫一遍全部历史 KV，读取量是 O(n × pos)；
现在每个位置只读一次，降到 O(pos)。**只影响 prefill**（decode 时 n=1，无变化）。

按 kvh-major 布局下实测的 58.4 MB/s 折算：

| 场景 | 改前 | 改后 | 省下 |
|---|---|---|---|
| 首轮 pos0=0, n=22 | 55 MB | 4.8 MB | 0.9 s |
| 第三轮 pos0=120 | 633 MB | 31 MB | 10.3 s |
| 长会话 pos0=500 | 2805 MB | 115 MB | 46 s |

第三轮那 633 MB **比模型权重的一半还多**，全花在重复读同一份 KV 上。

### 2. rope 连续访存 + cos/sin 预计算表

原来外层走 i、用 `vlse32` 跨 head 取数，stride = HEAD_DIM×4 = 512 字节，
每处只取 4 字节 —— 按 CLP 的 128 字节事务算，**有效载荷率仅 3%**。
每 token 触及约 172000 个离散地址，而真正要搬的数据只有 0.34 MB。

改成外层走 head：每个 head 的 512 字节连续，`e32m4`（vlmax=128）
正好覆盖半个 head。

另外 cos/sin **只与 pos 有关、28 层完全相同**，原来每层重算 64 组
powf/cosf/sinf（每 token 共 3584 组）。现在启动时打表（512 KB BSS），
运行时零超越函数。

## 该看什么

**decode 的 ms/token 不会有大变化** —— 这两项主要作用于 prefill。
真正的差别在**每轮问题的等待时间**：现在提问后要先等约 10 秒才开始吐字，
改完应当明显缩短。对演示观感而言，"反应快不快"往往比"吐字速度"更醒目。

**对比方法**：同一个问题在 L5 和 L6 各跑一次。重点看**从回车到第一个字出现**
的间隔，以及连续追问三四轮后这个间隔的增长。

## 关于投机解码

之前规划的投机解码（prompt lookup）已实测：命中率仅 2%、整体加速 1.10 倍。
Qwen3-0.6B 的中文输出短语级重复太少，这条路走不通。代码保留在 `SPEC`
开关下，默认关闭，本目录未启用。
