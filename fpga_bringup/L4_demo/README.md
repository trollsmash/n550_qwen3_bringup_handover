# L4 —— tile-major 权重的完整 demo

本目录是**自包含**的一套上板软件：固件、权重、分词器、地址表齐全，
不需要从 `L2_L3_fullmodel/` 拿任何文件。

## 文件

| 文件 | 写入地址 | 说明 |
|---|---|---|
| `qwen3_s2c.bin` | 0x80000000 | 固件（按 tile 权重的大小编译） |
| `w.bin` | 0x88000000 | 权重，**tile-major 布局** |
| `tok.bin` | 0xD0000000 | 分词器 |

`qwen3_s2c.elf` / `.diss` / `.sym` 是调试用，不写进板子。
真出了 TRAP，用 `riscv-unknown-elf-addr2line -e qwen3_s2c.elf <mepc>` 定位。

## 上板

1. 三块经 PCIe 后门写进 DDR（地址见上表，或 `addresses.txt`）
2. 放开复位
3. 串口 0x20100000，115200 8N1，终端编码设 UTF-8
4. 等 `>` 提示符 —— 出现即表示权重校验与分词器加载都过了

权重 1.11 GB 写入耗时较长，期间没有串口输出属正常。
host 侧也可以轮询 mailbox 0x87F00000，读到
`0xB0000002` 即就绪，不必靠猜。

## ⚠ 不要和 L2_L3_fullmodel/ 混用

固件把权重总长编进了二进制，`qwen3_init` 会严格核对：

- `L2_L3_fullmodel/` 的 `w.bin` 是 **row 布局**，1192100096 字节
- 本目录的 `w.bin` 是 **tile-major**，1192433664 字节

跨目录混搭会在启动时报 `QWEN3_ERR_SIZE` 停下。这是**明确的错误行**，
不是 trap，串口上一眼能认出来。

## 回答长度

每次回答最多 **256 个 token**（中文约 4.7 字节/token，合 384 个汉字左右），
模型吐出 EOS 会提前停，短问题不会硬凑满。

这个上限在编译时注入。`L2_L3_fullmodel/` 的固件用的是源码默认值 **1** ——
那是给 QEMU 定的（那里每多一个 token 就要再遍历一遍 1.1 GB 权重），
**问一句只答一两个字**。要看完整回答，用本目录这一份。

生成过程中按任意键可中止，不必等满。

## 多轮对话

**上一轮的内容会被记住**，可以接着追问：

```
> 中国最大的淡水湖在哪里
中国最大的淡水湖是鄱阳湖……

[67/1024] > 第二大呢
（这一轮能看到上一轮的问答）
```

提示符里的 `[已用/1024]` 是 KV cache 占用。上下文窗口
**1024 token**，按每轮约 70 token 估算能撑七八轮；
满了会自动开始新对话并明确提示，也可以随时输入 `new` 手动清空。

实现上是 KV cache 跨轮保留、新一轮从已用位置往后写，
**比每轮重新 prefill 整段历史更省** —— 省下的正好是一次完整的权重遍历。

## ⚠ 本版含硬件缺陷规避 HW-WAR-001

真机上存在这样一个缺陷：**AME 指令与它前面那条「非 AME 且无数据相关」的
指令之间会重叠执行**，导致配置来不及生效。2026-09-01 实测的表现是
`mtilem` 没配进去，随后第一条 `mlae16` 报 `mcause=2`（非法指令，
`mtval=0x04a7040b`）。

软件侧的规避：把一条 `mv` 与 AME 指令封进**同一个 asm 块**——
`mv` 写的正是 AME 指令要读的寄存器，构成 RAW 依赖迫使硬件等待；
同块也让编译器无法在中间插指令、或把 AME 指令变成分支落点。

覆盖 `set_tile` 的三条 `csrw` 与全部矩阵 load/store。
**`mzero` / `mfmacc` 不读任何通用寄存器，无法用此法规避**，
目前仍有 5 处暴露，需要 RTL 侧修复。

**RTL 修好之后请回退**，否则白白多执行那些 `mv`：

```bash
# 编译时加这个宏即可回到原始写法
KERNEL=ame OPS=rvv BOARD=s2c -DAME_NO_HW_WAR_001 ...

# 回退后复查有没有残留风险点
python3 src/tools/47_scan_ame_adjacency.py <你的.elf> riscv-unknown-elf-
```

扫描器会把所有 `b*` / `j` 的跳转来源也算作前驱，逐条判断数据相关性，
不只看物理上的前一条指令。

## 关于性能：现在不会更快

tile-major 把 GEMM 的行间跨度从 `K×2`（2048 或 6144 字节）压成 64 字节，
整个 tile 连续 8 KB 且 4 KB 对齐 —— 8 KB 恰好切成两个 ARLEN=63 的 burst，
不跨 4 KB 边界。

**但这套收益要 RTL 支持「stride 等于数据位宽时合并 burst」才能兑现。**
在那之前，L4 与 L3 的 token/s 应当基本一致；若明显更慢，那是 bug，请反馈。

现在就把它放上板，是为了确认这个布局在真机上数值正确 ——
RTL 改完之后直接换目录就能见效，不用再等一轮软件。

本版另外做了 **k 维双缓冲**：用两组 tile 寄存器交替，算 `tr0/tr1` 的
同时把下一块预取进 `tr2/tr3`，让访存通道在计算期间不空转。
它不减少一个字节的权重访存，收益上限就是"计算期间通道空闲的比例" ——
burst 之前访存慢到计算完全被淹没，这么写没意义；burst 之后才值得。
数值已在 QEMU 上验过与串行路径逐 token 一致。

若真机上出现 `mcause=2`（非法指令），先怀疑这里：
本版同时解开了"地址与 stride 钉死 a0/a1"的旧约束，
编译器现在会用到 `t1` 等寄存器。反馈给软件侧即可退回。

## 判据

与 L3 相同：能在 `>` 提示符下输入中文、得到中文回答即通过。
逐 token 的数值自检在 L2 做（不加载 `tok.bin` 即进回归模式）。
