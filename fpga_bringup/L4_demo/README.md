# L4 —— tile-major 权重的完整 demo

本目录是**自包含**的一套上板软件：固件、权重、分词器、地址表齐全，
不需要从 `L2_L3_fullmodel/` 拿任何文件。

## 文件

| 文件 | 写入地址 | 说明 |
|---|---|---|
| `qwen3_s2c.bin` | 0x80000000 | 固件（按 tile 权重的大小编译） |
| `w.bin` | 0x88000000 | 权重，**tile-major 布局** |
| `tok.bin` | 0xD0000000 | 分词器 |

`qwen3_s2c.elf` / `.diss` / `.sym` 是调试用，不写进板子。
真出了 TRAP，用 `riscv-unknown-elf-addr2line -e qwen3_s2c.elf <mepc>` 定位。

## 上板

1. 三块经 PCIe 后门写进 DDR（地址见上表，或 `addresses.txt`）
2. 放开复位
3. 串口 0x20100000，115200 8N1，终端编码设 UTF-8
4. 等 `>` 提示符 —— 出现即表示权重校验与分词器加载都过了

权重 1.11 GB 写入耗时较长，期间没有串口输出属正常。
host 侧也可以轮询 mailbox 0x87F00000，读到
`0xB0000002` 即就绪，不必靠猜。

## ⚠ 不要和 L2_L3_fullmodel/ 混用

固件把权重总长编进了二进制，`qwen3_init` 会严格核对：

- `L2_L3_fullmodel/` 的 `w.bin` 是 **row 布局**，1192100096 字节
- 本目录的 `w.bin` 是 **tile-major**，1192433664 字节

跨目录混搭会在启动时报 `QWEN3_ERR_SIZE` 停下。这是**明确的错误行**，
不是 trap，串口上一眼能认出来。

## 回答长度

每次回答最多 **64 个 token**（中文约 4.7 字节/token，合 96 个汉字左右），
模型吐出 EOS 会提前停，短问题不会硬凑满。

这个上限在编译时注入。`L2_L3_fullmodel/` 的固件用的是源码默认值 **1** ——
那是给 QEMU 定的（那里每多一个 token 就要再遍历一遍 1.1 GB 权重），
**问一句只答一两个字**。要看完整回答，用本目录这一份。

生成过程中按任意键可中止，不必等满。

## 关于性能：现在不会更快

tile-major 把 GEMM 的行间跨度从 `K×2`（2048 或 6144 字节）压成 64 字节，
整个 tile 连续 8 KB 且 4 KB 对齐 —— 8 KB 恰好切成两个 ARLEN=63 的 burst，
不跨 4 KB 边界。

**但这套收益要 RTL 支持「stride 等于数据位宽时合并 burst」才能兑现。**
在那之前，L4 与 L3 的 token/s 应当基本一致；若明显更慢，那是 bug，请反馈。

现在就把它放上板，是为了确认这个布局在真机上数值正确 ——
RTL 改完之后直接换目录就能见效，不用再等一轮软件。

## 判据

与 L3 相同：能在 `>` 提示符下输入中文、得到中文回答即通过。
逐 token 的数值自检在 L2 做（不加载 `tok.bin` 即进回归模式）。
